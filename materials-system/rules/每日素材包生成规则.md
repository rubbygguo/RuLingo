# 每日素材包生成规则

这份文档定义每天生成素材包时应该遵循的流程。目标是让素材包不是随机链接集合，而是围绕学习计划、近期主题和技能比例生成的可执行训练包。

## 1. 输出位置

每日素材包和后续练习沉淀统一写入当天学习工作区：

```text
materials-system/daily-packs/YYYY-MM-DD/
```

示例：

```text
materials-system/daily-packs/2026-05-12/
  01-今日素材包_主题.html
  03-练习反馈原文_来源.md
  04-练习反馈结构化沉淀.md
  05-后续计划建议.md
  06-系统记录候选.md
```

`materials-system/daily-packs/` 不同步到 Git，只作为本地每日学习材料。项目代码里不沉淀长期素材库。

每日学习工作区结构遵守：

```text
materials-system/rules/每日学习工作区设计规则.md
```

## 2. 每日生成流程

每天生成前按顺序执行：

1. 读取当天计划，例如 `data/plans/daily/YYYY-MM-DD.json`。
2. 回溯最近 7 天每日素材包，必要时扩大到最近 14 天。
3. 统计最近素材覆盖的场景、技能和 topic。
4. 判断今天应该补充或延续的方向。
5. 搜索并筛选有质量的外部素材。
6. 为每个素材生成适用场景、训练技能、建议用法、可积累表达和输出任务。
7. 生成当天素材包 HTML，并放入日期子文件夹。
8. 如果包含口语或听说训练，在当天 HTML 内嵌可复制给 ChatGPT 的语音陪练指令包，并提供一键复制按钮；除非用户明确要求，不再单独生成 Markdown 指令包。
9. 学习完成后，用户可把 ChatGPT 反馈或复盘发给 Codex。
10. Codex 按每日学习工作区规则生成反馈原文、结构化沉淀、后续计划建议和系统记录候选。
11. 有价值内容后续上传到系统后台数据库，不保存在项目代码里。

## 3. 回溯检查

每日生成时需要避免主题随机漂移。

回溯时检查：

- 最近 7 天学过哪些 topic
- 工作、社交、学术积累、其他补充话题分别出现几次
- 听、说、读、写分别练了几次
- 哪些素材值得延续
- 哪些主题已经连续出现，需要暂时避开
- 哪些真实任务还没覆盖，例如 office hour、seminar Q&A、presentation、small talk、academic email

## 4. 默认场景比例

当前默认比例只是阶段性假设，可随时调整：

```text
工作：50%
社交：30%
学术积累：10%
其他补充话题：10%
```

如果近期有课程 deadline、presentation、面试、实习、求职或社交需求，应优先按真实任务调整比例。

## 5. 默认素材标准

优先选择：

- 有 transcript、字幕、model text 或练习题的材料
- 来源本身已经提炼 useful phrases、language focus 或 model answers 时，优先直接使用来源内表达，并标注这些表达来自原材料
- 难度在 B2-C1 左右的材料
- 能转化成口语或写作输出的材料
- 与香港研究生生活、学术任务或职业准备相关的材料
- 来源稳定、语言质量可靠的材料

避免选择：

- 只有链接但无法形成输出任务的材料
- 用主题相近但来源中未出现的自拟表达，替代原材料已经给出的 useful phrases
- 过长、过散、整理成本太高的材料
- 连续重复最近几天已经练过的 topic
- 无来源或语言质量不稳定的材料

## 6. 每日素材包格式

每日素材包默认输出为独立 HTML 文件：

```text
01-今日素材包_主题.html
```

HTML 应适合作为当天学习入口直接打开使用。它应包含完整页面结构、基础样式和清晰的学习顺序，不依赖项目网站运行，也不要求用户再阅读 Markdown 原文。

每日素材包至少包含：

- 今日计划对应
- 今日主题建议
- 素材清单
- 每个素材的来源链接、难度、场景、技能和使用方式
- 可积累表达
- 如果包含口语或听说输出训练，必须在 HTML 内嵌完整语音陪练指令包，并提供一键复制按钮；语音指令包内容仍遵守 `materials-system/rules/语音陪练指令包设计规则.md`
- 今日输出任务
- 推荐执行顺序
- 今日最建议主动使用的表达
- 今日复盘问题
- 轻交互练习区，例如写作输入、复盘输入、表达勾选、字数统计、自查清单和一键复制反馈请求

HTML 设计要求：

- 使用语义化 HTML，例如 `header`、`main`、`section`、`article`、`aside`。
- 内嵌少量 CSS，保证离线打开时也有清晰排版。
- 页面第一屏应直接呈现今日主题、学习目标和执行顺序。
- 素材链接、表达、任务和复盘问题应分区展示，方便边学边用。
- 每个练习不能只写一句任务说明，应列出具体题目、步骤、要求、可套用结构和完成标准。
- 轻交互只做本地辅助：可以用 `localStorage` 保存草稿、统计字数、检查关键词、勾选完成项、生成可复制给 Codex 的反馈请求。
- 不在每日 HTML 中直接接入 AI 评分、后端服务或 API 密钥；需要反馈时生成结构化文本，由用户复制回 Codex 或 ChatGPT。
- 不把语音陪练指令包改写成网页交互内容；只提供跳转、复制提醒或简短引用。

## 7. 学后沉淀流程

每日素材包只是当天学习入口，不是长期知识库。

学习完成后，用户可以把输出、复盘或口头反馈发给 Codex。Codex 负责总结：

- 真正值得保留的表达
- 用户自己的高价值例句
- 需要复习的错误或卡点
- 值得进入后台数据库的 topic、技能标签和任务记录

这些内容后续上传到系统后台数据库。上传字段、后台结构和审核流程另行设计。

## 8. 规则调整方式

用户可以直接用自然语言调整规则，例如：

```text
这周求职优先，把职业英语提高到 40%。
最近少放阅读，多给我听力和口语。
素材太难了，降到 B1-B2。
这几天多练 office hour 和 small talk。
```

调整后，应更新本规则或相关规则文档，并从下一次素材包开始执行。
