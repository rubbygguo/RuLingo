# 每日素材包生成规则

这份文档定义每天生成素材包时应该遵循的流程。目标是让素材包不是随机链接集合，而是围绕学习计划、近期主题和技能比例生成的可执行训练包。

## 1. 输出形态

每日素材包现在默认生成为数据库可渲染的 DailyPack snapshot JSON，而不是独立 HTML。

生成文件先写入：

```text
data/daily-packs/YYYY-MM-DD.json
```

之后由 Codex 调用上传脚本写入 CloudBase MySQL。RuLingo `/daily-pack` 页面只从数据库读取；如果当天数据库没有素材包，应显示空状态并提示生成素材包，不回退读取本地 JSON。

每次生成当天素材包都视为 regenerate，并覆盖当天当前有效 snapshot。同一天重复生成时，按 CloudBase 自动写入的 `owner + date_key` 覆盖当天 snapshot，不创建重复记录，不区分 inserted / updated，不保留多版本。`owner` 是 CloudBase 权限字段，上传脚本应登录目标用户，让 CloudBase 自动填充，不应手动写入。

如果重新生成时本地当天 JSON 已存在，例如 `data/daily-packs/YYYY-MM-DD.json`，不要直接覆盖。Codex 必须先读取上一版 JSON，向用户总结其中的主题、素材、section、unit 和 learningItems，并确认本次是否复用这些内容。用户可能完全采纳、部分采纳或完全不采纳上一版内容；Codex 应根据对话判断复用范围，再决定是否额外补充新主题、新素材或新语言点。只有在用户确认复用策略和新生成方向后，才可以写入新版 JSON 并上传覆盖。

本地每日学习工作区仍用于保存练后反馈、结构化沉淀、后续建议等过程文件：

```text
materials-system/daily-packs/YYYY-MM-DD/
```

示例：

```text
materials-system/daily-packs/2026-05-12/
  03-练习反馈原文_来源.md
  04-练习反馈结构化沉淀.md
  05-后续计划建议.md
  06-系统记录候选.md
```

`materials-system/daily-packs/` 不同步到 Git，只作为本地每日学习材料。项目代码里不沉淀长期素材库。

每日学习工作区结构遵守：

```text
materials-system/rules/每日学习工作区设计规则.md
```

## 2. 每日生成流程

每天生成前按顺序执行：

1. 读取当天计划，例如 `data/plans/daily/YYYY-MM-DD.json`；如果不存在，用 `data/plans/weekly.json` 和用户当天输入补位。
2. 读取 `data/plans/weekly.json`，判断阶段目标和默认节奏。
3. 回溯最近 7 天每日素材包和 DailyPack snapshot，必要时扩大到最近 14 天。
4. 回溯最近 7-14 天的结构化反馈文件，例如 `materials-system/daily-packs/**/04-练习反馈结构化沉淀*.md`。
5. 统计最近素材覆盖的场景、技能和 topic。
6. 判断今天应该补充、复用或暂时避开的方向。
7. 检查本地是否已存在当天 snapshot JSON，例如 `data/daily-packs/YYYY-MM-DD.json`。
8. 如果当天 JSON 已存在，先读取并总结其中的主题、素材、section、unit 和 learningItems，向用户确认本次重新生成是否要复用已有内容；用户可能完全采纳、部分采纳或完全不采纳。Codex 应根据对话判断复用范围，再决定是否额外补充新主题、新素材或新语言点。
9. 通过对话向用户确认今天的时长、技能侧重、真实需求、难度和主题方向；用户确认前不生成最终 JSON，不检索外部素材，不上传。
10. 搜索并筛选有质量的外部素材。
11. 为每个练习单元生成素材、适用场景、训练技能、建议用法、语言点预处理和必要的输出任务。
12. 生成当天 DailyPack snapshot JSON。
13. 调用上传脚本写入 CloudBase MySQL；生成结果始终覆盖当天当前有效素材包。
14. 学习完成后，系统收集完成状态、任务回答、语言点标记、语言点备注、unit 自由反馈和语音反馈，Codex 在对话中引导复盘。
15. Codex 按每日学习工作区规则生成反馈原文、结构化沉淀、后续计划建议和系统记录候选。

## 3. 回溯检查

每日生成时需要避免主题随机漂移。

回溯时检查：

- 最近 7 天学过哪些 topic
- 工作、社交、学术积累、其他补充话题分别出现几次
- 听、说、读、写分别练了几次
- 哪些素材值得延续
- 哪些主题已经连续出现，需要暂时避开
- 哪些真实任务还没覆盖，例如 office hour、seminar Q&A、presentation、small talk、academic email

## 4. 默认场景比例

当前默认比例只是阶段性假设，可随时调整：

```text
工作：50%
社交：30%
学术积累：10%
其他补充话题：10%
```

如果近期有课程 deadline、presentation、面试、实习、求职或社交需求，应优先按真实任务调整比例。

## 5. 默认素材标准

优先选择：

- 有 transcript、字幕、model text 或练习题的材料
- 来源本身已经提炼 useful phrases、language focus 或 model answers 时，优先直接使用来源内表达，并标注这些表达来自原材料
- 难度在 B2-C1 左右的材料
- 能转化成口语或写作输出的材料
- 与香港研究生生活、学术任务或职业准备相关的材料
- 来源稳定、语言质量可靠的材料

避免选择：

- 只有链接但无法形成输出任务的材料
- 用主题相近但来源中未出现的自拟表达，替代原材料已经给出的 useful phrases
- 过长、过散、整理成本太高的材料
- 连续重复最近几天已经练过的 topic
- 无来源或语言质量不稳定的材料

## 6. DailyPack Snapshot 格式

每日素材包默认输出为 snapshot wrapper：

```json
{
  "id": "daily-pack-snapshot-YYYY-MM-DD",
  "date": "YYYY-MM-DD",
  "schemaVersion": "daily_pack_snapshot.v1",
  "generatedBy": "codex",
  "createdAt": "YYYY-MM-DDTHH:mm:ss+08:00",
  "packJson": {}
}
```

`packJson` 至少包含：

- `id`
- `date`
- `theme`
- `estimatedMinutes`
- `summary`
- `sections`
- `feedbackPackagePrompt`

`expressionPool` 暂不作为必填字段，也暂不要求生成。后续如果恢复跨技能表达池，再单独更新本规则。

### 6.1 顶层结构

DailyPack 按听、说、读、写四类技能组织。每个技能 section 结构统一：

```json
{
  "id": "listening",
  "skill": "listening",
  "label": "听",
  "theme": "今日主题",
  "goal": "今日目标",
  "units": []
}
```

每个 unit 是一个学习单元，练习任务必须跟随单元，不要把素材和练习拆成平行的大模块：

```json
{
  "id": "unit-id",
  "title": "练习单元标题",
  "tags": [],
  "instructions": "练习说明",
  "materials": [],
  "learningItems": [],
  "tasks": []
}
```

`targetExpressions` 已废弃，新生成的 DailyPack 不应再输出该字段。需要预处理、复习或标记的表达与语言点统一放入 `learningItems[]`。

生成后检查时，如果发现 `targetExpressions`，应删除并把其中仍有价值的内容改写成 `learningItems[]`。

### 6.2 素材类型

素材是支撑练习发生的输入，不等于外部链接。`materials[]` 可使用：

- `external_link`：外部素材，包含 `title`、`source`、`url`、`description`。
- `scenario`：内嵌场景素材，常用于口语或写作任务。
- `copyable_prompt`：可复制到外部工具的指令包，例如 ChatGPT 语音陪练指令。
- `text`：内嵌短文本、范文片段或 model answer。

语音陪练指令包应作为 `copyable_prompt` 类型素材；内容仍遵守：

```text
materials-system/rules/语音陪练指令包设计规则.md
```

### 6.3 学习对象：learningItems

`learningItems[]` 是 unit 内可学习、可标记、可反馈的语言点集合。它优先服务听力 transcript 的预处理，也可在阅读、口语、写作中按需要使用。

每个 learning item 至少包含：

- `id`
- `type`
- `text`

推荐字段：

- `meaning`：中文解释或简明说明。
- `sourceSentence`：来自原材料的原句或关键片段。
- `note`：使用场景、听力提示、语义区别或学习提醒。
- `reusePrompt`：可选，提示用户如何迁移使用该表达或句型。

`type` 可使用：

- `keyword`：关键词。
- `phrase`：重点词组。
- `expression`：重点表达。
- `sentence_pattern`：重点句型。
- `listening_cue`：听力抓手，例如转折、因果、举例、总结信号。
- `missed_sound`：易漏听表达，例如弱读、连读、口语缩略。

暂不使用 `retell_frame`。复述支架后续如需恢复，再单独更新规则。

听力 unit 的 learning item 数量暂不设硬性上限，按 transcript 内容决定。原则是宁可少而准，不要为了凑数量塞入低价值词汇。

示例：

```json
{
  "id": "li-fall-behind",
  "type": "keyword",
  "text": "fall behind",
  "meaning": "落后，跟不上",
  "sourceSentence": "I started to fall behind.",
  "note": "可以描述学习进度、项目进度或任务积压。"
}
```

### 6.4 练习任务

`tasks[]` 表示用户需要完成的学习动作或输出任务。非听力 section 通常应包含任务；听力 section 当前可以不生成 `tasks`，只提供 `materials[]`、`learningItems[]` 和 unit 自由反馈入口。

任务对象包含：

- `id`
- `prompt`
- `responseType`: `none`、`text` 或 `checklist`
- `answerLabel`：当 `responseType` 为 `text` 时使用
- `completed`: 生成时恒为 `false`

不要把用户回答、完成状态或练后反馈写进 snapshot JSON。snapshot 是“题目”；用户 response 是“答卷”；Codex 整理的是“批改和沉淀”。

听力 section 当前不生成传统 comprehension questions，也不为了完成度硬塞听力任务。听力语言点标记暂不计入任务完成度。

### 6.5 听力 section 生成要求

听力 section 的核心目标是把 transcript 预处理成可理解、可标记、可反馈的语言材料，而不是围绕 transcript 生成传统习题。

听力 unit 应包含：

- `materials[]`：外部音频/视频链接，以及必要时内嵌 transcript。
- `learningItems[]`：从 transcript 中提取的关键词、重点词组、重点表达、重点句型、听力抓手、易漏听表达。
- `tasks: []`：当前阶段保持为空。

听力 unit 不应包含：

- comprehension questions。
- 为了完成度而设计的形式化选择题、判断题或问答题。
- `targetExpressions`。
- 复述支架。

提取 learning items 时优先选择：

- 影响理解主旨或细节的词/短语。
- transcript 中真实出现、值得吸收的地道表达。
- 能迁移到用户学习、生活、学术或工作场景的句型。
- 听力中容易漏掉的结构信号，例如转折、递进、因果、举例、总结。
- 弱读、连读、缩略或口语化表达导致的易漏听点。

避免：

- 随机摘出生词。
- 用 transcript 中没有出现的表达替代原材料表达。
- 把所有生词都塞进 learningItems。
- 把阅读式词汇表伪装成听力语言点。

### 6.6 表达池

`packJson.expressionPool` 暂时不生成，页面也暂时隐藏表达池入口。

如果后续恢复表达池，应重新定义它与 `learningItems` 的关系。当前阶段不要同时输出 `targetExpressions`、`expressionPool` 和 `learningItems` 三套表达结构，避免重复和混乱。

生成后检查时，如果发现 `expressionPool`，应删除；除非用户之后明确要求恢复表达池。

## 7. 学后沉淀流程

每日素材包只是当天学习入口，不是长期知识库。

学习完成后，用户可以把输出、复盘或口头反馈发给 Codex。Codex 负责总结：

- 真正值得保留的表达
- 用户自己的高价值例句
- 需要复习的错误或卡点
- 用户标记为不熟的 learning items
- 用户标记为忽略的 learning items
- 单个 learning item 备注和 unit 自由反馈
- 值得进入后台数据库的 topic、技能标签和任务记录

这些内容后续上传到系统后台数据库。上传字段、后台结构和审核流程另行设计。

## 8. 规则调整方式

用户可以直接用自然语言调整规则，例如：

```text
这周求职优先，把职业英语提高到 40%。
最近少放阅读，多给我听力和口语。
素材太难了，降到 B1-B2。
这几天多练 office hour 和 small talk。
```

调整后，应更新本规则或相关规则文档，并从下一次素材包开始执行。
