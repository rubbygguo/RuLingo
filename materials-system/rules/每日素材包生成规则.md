# 每日素材包生成规则

这份文档是 RuLingo daily pack 的生成准则。核心目标是：每天用少量、真实、可追溯的英文材料，围绕一个主题打通听、读、说、写，形成可执行的学习闭环。

## 1. 核心原则

### 1.1 真实素材优先

Daily pack 必须由真实外部素材驱动。Codex 可以做材料筛选、语言点解释、任务设计和反馈整理，但不能冒充素材作者。

禁止：

- 根据标题、网站名、主题或记忆猜 URL。
- 编造 BBC、British Council、TED-Ed、YouGlish 等来源的文章、句子、transcript 或例句。
- 把 AI 自写内容包装成外部素材。
- 用打不开、无内容、404、搜索结果页、占位页、短链或需要登录但无法确认内容的页面作为素材。

允许：

- Codex 设计口语 role-play、写作题、复述任务、检查清单和语音陪练指令。
- Codex 基于真实素材解释表达、改写成适合用户迁移的练习任务。
- `scenario`、`text`、`copyable_prompt` 用作练习支架，但必须明确它们是练习设计，不是外部来源材料。

### 1.2 一个主题打通听说读写

每天只选一个主主题，例如：

- fitness routine
- group project discussion
- job interview
- weekend plan
- conflict at work
- travel experience
- shopping for home decoration

听力、阅读、口语、写作、复习表达都应围绕这个主题。不要把不同来源的材料随机拼在一起。

同一主题可以连续练 2-3 天。优先让高价值表达反复出现，帮助用户真正说出口。

### 1.3 小而完整

默认控制在 40 分钟以内。用户很忙时，优先保留 Listening + Speaking。

建议结构：

| 模块 | 内容 | 时间 |
| --- | --- | --- |
| Listening | 1 段短音频/视频 + transcript/subtitles + 3 个跟读句 | 8 分钟 |
| Reading | 1 篇短文或短页面，约 150-250 words | 8 分钟 |
| Speaking | 4-6 轮情景对话或观点追问 | 10 分钟 |
| Writing | 80-120 words 短写作 | 10 分钟 |
| Review | 5 个来自真实素材的可复用表达 | 4 分钟 |

## 2. 推荐素材来源

优先使用用户已确认可打开、免费、低门槛、稳定、适合英语学习者的来源。素材源按用途分级；生成 daily pack 时先从主力源找，找不到合适材料再用备选源。

### 2.1 主力听力源

- ELLLO：适合日常对话、自然口语、听力 transcript 和跟读句。
- Breaking News English：适合新闻/社会话题，有分级文本、音频和练习。
- Listen A Minute：适合很短的主题听力和轻量 daily pack。
- BBC Learning English：适合自然表达、语法点、职场表达和短视频；能确认 transcript / subtitles 时优先使用。
- TED-Ed：适合观点表达和知识类主题；只有能核对 transcript / subtitles 时才提取原句。

听力材料必须有可确认的 transcript、字幕或页面文本。没有 transcript 的材料不能生成听力 `learningItems`，也不能伪造 source sentence。

### 2.2 备选听力源

- Randall's ESL Cyber Listening Lab：适合听力理解和生活场景；如果页面、音频和文本都可访问，可作为主力源补充。
- British Council LearnEnglish / LearnEnglish Teens：适合分级听力、生活话题和练习题；若页面在当天可打开，可作为听力或阅读来源。

### 2.3 阅读源

- British Council LearnEnglish
- British Council LearnEnglish Teens
- Simple English Wikipedia
- Breaking News English text pages
- Cambridge English Activities
- TED-Ed lesson pages

阅读材料应短、清楚、可转化成口语或写作输出。避免过长、过散、整理成本过高的文章。

### 2.4 口语和发音源

- YouGlish：用于真实发音和语境参考。
- ELLLO：用于自然对话表达和跟读句。
- BBC Learning English：用于日常表达、职场表达和 pronunciation。
- British Council speaking / business communication materials。
- TED-Ed：用于观点表达。

YouGlish 只作为发音和真实语境参考。只有在字幕、页面文本或可核对片段中确认过的句子，才可以作为原句引用。

### 2.5 写作和小练习

- Cambridge Write & Improve
- Cambridge English Activities
- British Council writing materials
- Breaking News English discussion / writing prompts

写作题可以由 Codex 根据当天真实素材设计。Write & Improve 更适合作为用户提交写作后的外部反馈工具，不必每天强制使用。

## 3. 输出形态

Daily pack 输出为数据库可渲染的 snapshot JSON：

```text
materials-system/daily-packs/YYYY-MM-DD/daily-pack-snapshot.json
```

之后由上传脚本写入 CloudBase MySQL。RuLingo `/daily-pack` 页面只从数据库读取；如果当天数据库没有素材包，页面显示空状态，不回退读取本地 JSON。

同一天重新生成视为 regenerate，上传后覆盖当天当前有效 snapshot。覆盖依据是 CloudBase 自动写入的 `owner + date_key`。不要创建重复记录，也不要在用户说明里区分 inserted / updated。

如果本地当天 JSON 已存在，Codex 必须先读取上一版，向用户总结主题、素材、sections、units 和 learningItems，并确认复用策略。用户确认前不要覆盖本地 JSON，也不要上传。

本地每日学习工作区仍用于保存练后反馈、结构化沉淀和后续建议：

```text
materials-system/daily-packs/YYYY-MM-DD/
```

工作区结构遵守：

```text
materials-system/rules/每日学习工作区设计规则.md
```

## 4. 生成流程

每天生成前按顺序执行：

1. 读取当前 `/today` 固定任务定义（`src/todayPlanData.js`），并结合用户输入补位。
2. 回溯最近 7 天 daily pack、DailyPack snapshot 和结构化反馈；必要时扩大到 14 天。
3. 统计最近主题、场景、技能比例和重复内容，判断今天应该延续、补充或避开的方向。
4. 如果当天 JSON 已存在，先总结上一版并询问是否复用。
5. 向用户确认今天主题、时长、技能侧重、难度和真实需求。用户确认前不生成最终 JSON、不检索外部素材、不上传。
6. 围绕确认主题搜索真实外部素材。优先选择可打开、有 transcript / 字幕 / 文本 / 练习题 / useful phrases 的材料。
7. 打开并核对每个候选 URL。确认页面内容、标题和来源匹配，优先使用无 tracking 参数的 canonical URL。
8. 为听力材料确认 transcript 或字幕。不能确认 transcript 时，不使用它生成听力语言点。
9. 从真实素材中提取 useful expressions、shadowing sentences、source sentences 和 learningItems。
10. 基于这些素材设计 speaking、writing、review 任务。
11. 生成 DailyPack snapshot JSON。
12. 执行来源审计。任何 URL、transcript、sourceSentence 或表达无法追溯时，删除或替换，不得上传。
13. 用户确认生成结果后，再调用上传脚本覆盖当天 snapshot。
14. 学习完成后，根据页面收集的完成状态、回答、语言点标记、备注和自由反馈，引导复盘并生成结构化沉淀。

## 5. 素材标准

优先选择：

- 真实可打开的来源页面。
- 有 transcript、字幕、model text、练习题或 useful phrases 的材料。
- B1-C1 之间，默认贴近 IELTS 6.5。
- 语言自然、来源稳定、适合反复跟读或迁移输出的材料。
- 能服务香港研究生生活、学术任务、职业准备或日常沟通的材料。
- 能和当天主题形成听、读、说、写闭环的材料。

避免选择：

- 只有链接但无法形成输出任务的材料。
- 无法验证真实内容的链接。
- 过长、过散、需要大量整理的材料。
- 来源质量不稳定或广告、论坛、低质量转载页面。
- 连续重复最近几天已经练过且没有新角度的 topic。
- 来源中没有出现，却由 Codex 自拟出来冒充“材料表达”的语言点。

## 6. DailyPack Snapshot 结构

Snapshot wrapper：

```json
{
  "id": "daily-pack-snapshot-YYYY-MM-DD",
  "date": "YYYY-MM-DD",
  "schemaVersion": "daily_pack_snapshot.v1",
  "generatedBy": "codex",
  "createdAt": "YYYY-MM-DDTHH:mm:ss+08:00",
  "packJson": {}
}
```

`packJson` 至少包含：

- `id`
- `date`
- `theme`
- `estimatedMinutes`
- `summary`
- `sections`
- `feedbackPackagePrompt`

暂不生成 `expressionPool`。`targetExpressions` 已废弃，不应出现在新 pack 里。

### 6.1 Section 和 Unit

默认按听、读、说、写组织：

```json
{
  "id": "listening",
  "skill": "listening",
  "label": "听",
  "theme": "今日主题",
  "goal": "今日目标",
  "units": []
}
```

每个 unit 是一个学习单元，素材、语言点和任务都跟随 unit：

```json
{
  "id": "unit-id",
  "title": "练习单元标题",
  "tags": [],
  "instructions": "练习说明",
  "materials": [],
  "learningItems": [],
  "tasks": []
}
```

### 6.2 Material

`materials[]` 支持：

- `external_link`：真实外部素材，包含 `title`、`source`、`url`、`description`。
- `scenario`：Codex 设计的练习场景，必须基于当天真实素材主题。
- `copyable_prompt`：可复制到外部工具的指令包，例如 ChatGPT 语音陪练指令。
- `text`：短文本、写作题、检查清单或练习支架。若为 Codex 自写，必须明确是练习支架，不得冒充外部来源。

`external_link.url` 要求：

- 必须是打开并核对过的真实页面。
- 页面内容必须与 `title`、`source`、`description` 匹配。
- 禁止使用搜索结果页、占位域名、localhost、短链、无内容页或无法访问页面。
- 禁止根据标题或网站结构猜 slug。
- 如果页面跳转，优先记录最终可访问的 canonical URL。

语音陪练指令包遵守：

```text
materials-system/rules/语音陪练指令包设计规则.md
```

### 6.3 Learning Items

`learningItems[]` 是当天可学习、可标记、可反馈的语言点。它们必须来自真实素材，不能根据主题自拟。

每个 item 至少包含：

- `id`
- `type`
- `text`

推荐字段：

- `meaning`：中文解释或简明说明。
- `sourceSentence`：真实素材中的原句或连续片段。
- `note`：用法、听力提示、语义区别或迁移提醒。
- `reusePrompt`：提示用户如何迁移使用。

`type` 可使用：

- `keyword`
- `phrase`
- `expression`
- `sentence_pattern`
- `listening_cue`
- `missed_sound`

听力 `learningItems` 额外强制：

- 必须从该 unit 的 transcript / subtitle / 页面文本中提取。
- `sourceSentence` 必填，且必须是原文真实出现的连续片段。
- `text` 必须能在 `sourceSentence` 中直接找到；`listening_cue` 至少要有对应信号词或结构片段。
- `note` 可以解释，但不能引入原文没有的新表达作为学习项。
- 缺少 transcript 时，听力 `learningItems` 必须为空，并在说明中写清楚原因。

阅读、口语、写作中的可复用表达也应优先来自当天真实素材。Codex 可以补充迁移提示，但不能把自拟表达写成来源表达。

### 6.4 Tasks

`tasks[]` 是用户要完成的动作或输出任务。

任务对象包含：

- `id`
- `prompt`
- `responseType`: `none`、`text` 或 `checklist`
- `answerLabel`：当 `responseType` 为 `text` 时使用
- `completed`: 生成时恒为 `false`

不要把用户回答、完成状态或练后反馈写进 snapshot JSON。snapshot 是“题目”；用户 response 是“答卷”；Codex 后续整理的是“批改和沉淀”。

## 7. 来源审计清单

生成后必须逐项检查：

1. 每个 `external_link.url` 是否真实打开过，且内容与标题和来源匹配。
2. 是否存在占位链接、搜索结果页、猜测 URL、短链、404、登录墙或无内容页面。
3. 听力材料是否有 transcript / subtitle / 页面文本；没有则不得生成听力 `learningItems`。
4. 每个 `learningItems[].sourceSentence` 是否来自对应真实素材。
5. 每个 `learningItems[].text` 是否能在 `sourceSentence` 中找到。
6. `shadowing sentences` 是否来自听力 transcript 或可核对字幕。
7. `useful expressions` 是否来自当天真实素材，或是否明确标注为 Codex 设计的练习支架。
8. speaking、writing、review 任务是否围绕同一主题复用当天材料表达。
9. JSON 中是否仍有 `targetExpressions` 或不必要的 `expressionPool`。
10. 是否把用户回答、完成状态或练后反馈误写进 snapshot。

审计失败时，删除或替换问题内容。不要为了凑数量补写虚构材料。

## 8. 学后沉淀

Daily pack 是当天学习入口，不是长期知识库。

学习完成后，Codex 根据用户输出、语言点标记、备注和自由反馈整理：

- 真正值得保留的表达。
- 用户自己的高价值例句。
- 需要复习的错误或卡点。
- 用户标记为不熟或忽略的 learning items。
- 单个 learning item 备注和 unit 自由反馈。
- 后续 daily pack 应延续或避开的主题。

沉淀文件遵守：

```text
materials-system/rules/每日学习工作区设计规则.md
```

## 9. 规则调整

用户可以直接用自然语言调整规则，例如：

```text
这周求职优先，把职业英语提高到 40%。
最近少放阅读，多给我听力和口语。
素材太难了，降到 B1-B2。
这几天多练 office hour 和 small talk。
fitness 这个主题连续练三天。
```

调整后，应更新本规则或相关规则文档，并从下一次素材包开始执行。
