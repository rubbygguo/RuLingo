# 每日练习复盘规则

## 目标

Codex 通过 CloudBase 拉取当天 RuLingo 素材包和用户保存的答案后，在对话里帮助用户完成复盘。复盘重点不是打分，而是找出真实卡点、保留可复用表达，并决定下一次练习动作。

## 开场

优先先问 1-3 个关键问题，不要让用户填表。

问题应该来自当天数据，例如：

- 用户写了答案但明显不完整、乱码、占位或偏题的任务。
- 用户标记为 `unfamiliar` 的学习材料。
- 用户在 unit feedback 里留下的自由笔记。
- 当天主题中最需要迁移到真实场景的表达。

如果用户明确要求直接总结，可以跳过提问，直接给复盘。

## 分析顺序

1. 先看 `merged.theme` 和 `merged.summary`，确认当天场景。
2. 看 `merged.tasks`：
   - 区分已完成、有文字答案、仅勾选完成、未完成。
   - 对文字答案检查是否回应了 prompt。
   - 对明显乱码、占位、空泛答案，直接指出“这条还不能作为有效练习结果”。
3. 看 `merged.learningItems`：
   - 优先关注 `status: "unfamiliar"`。
   - 对 `status: "mastered"` 的项目，除非答案中能看到使用证据，否则只视为自评。
4. 看 `merged.unitFeedback`：
   - 把自由笔记当作用户即时感受，而不是最终结论。
   - 如果笔记无法理解，可以追问。

## 复盘输出

用户回答开场问题后，整理为：

1. 完成摘要
2. 主要卡点
3. 值得保留的表达
4. 用户例句或可改写句
5. 下一次练习建议

保持短而具体。不要泛泛鼓励。

## 语言记忆建议

只有当某个表达满足至少一项条件时，才建议加入 RuLingo memory：

- 用户明确不会或标记 unfamiliar。
- 表达与当天真实场景高度相关。
- 用户答案中暴露出该表达的替代需求。
- 未来一周很可能复用。

建议后等待用户确认。不要自动上传。

## 不要做

- 不要要求用户复制反馈包，除非数据库拉取失败。
- 不要把 checkbox-only task 当作语言质量证据。
- 不要把 `mastered` 当作真正掌握的证明。
- 不要在没有用户确认时写入 memory。
- 不要泄露 CloudBase 配置、token、密码或本地配置内容。
