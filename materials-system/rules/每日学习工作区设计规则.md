# 每日学习工作区设计规则

这份文档定义 `materials-system/daily-packs/YYYY-MM-DD/` 的组织方式。每日文件夹不只是“素材包存放处”，而是当天完整学习过程的临时工作区，记录从素材生成、口语练习、反馈沉淀到后续计划建议的全过程。

## 1. 核心定位

每日学习工作区承担两类任务：

- 学习入口：保存当天初始素材、练习任务、语音陪练指令包。
- 过程沉淀：保存用户练习后的反馈、Codex 对反馈的结构化总结、后续计划建议。

这些文件默认仍属于本地每日材料，不进入 Git。真正长期保留或展示到 RuLingo 系统中的内容，应后续通过单独的数据同步流程进入系统记录或后台数据库。

## 2. 推荐文件结构

每天的文件夹建议使用以下结构：

```text
materials-system/daily-packs/YYYY-MM-DD/
  01-今日素材包_主题.html
  03-练习反馈原文_来源.md
  04-练习反馈结构化沉淀.md
  05-后续计划建议.md
  06-系统记录候选.md
```

如果当天没有完成练习，可以只保留 `01-今日素材包_主题.html`。语音或口语练习指令默认内嵌在 HTML 中，除非用户明确要求单独保存 Markdown。

如果一天内做了多次练习，可以追加编号：

```text
03-练习反馈原文_ChatGPT_语音陪练1.md
03-练习反馈原文_ChatGPT_语音陪练2.md
04-练习反馈结构化沉淀_语音陪练1.md
04-练习反馈结构化沉淀_语音陪练2.md
```

## 3. 文件职责

### 3.1 `01-今日素材包_主题.html`

由 Codex 在学习前生成。

用途：作为当天可直接打开的学习入口，承载今日材料、任务和执行顺序。它默认是独立 HTML 文件，可以离线打开，不依赖 RuLingo 前端服务。

内容包括：

- 今日计划对应
- 今日主题建议
- 素材清单
- 来源链接和使用方式
- 来源内可积累表达
- 今日输出任务
- 推荐执行顺序
- 今日复盘问题

格式要求：

- 使用完整 HTML 文档结构，包括 `<!doctype html>`、`html`、`head`、`body`。
- 内嵌必要 CSS，保证页面打开后有清晰的标题层级、任务区块、素材卡片和复盘区。
- 第一屏直接展示今日主题、学习目标和推荐执行顺序。
- 素材来源链接必须可点击，外部素材旁边写明用途和训练技能。
- 表达、输出任务和复盘问题应方便边学边查看。

如果当天包含口语或听说输出训练，应在 HTML 中内嵌完整语音指令包，并提供一键复制到剪贴板按钮，方便用户直接粘贴给 ChatGPT 语音模式。

### 3.2 HTML 内嵌语音陪练指令包

由 Codex 在学习前生成，并写入 `01-今日素材包_主题.html`。

用途：用户整段复制给 ChatGPT 语音模式，开始口语练习。

必须遵守：

```text
materials-system/rules/语音陪练指令包设计规则.md
```

内容包括：

- 角色设定
- 具体练习场景
- 用户练习目标
- 目标表达
- 对话规则
- 反馈格式

### 3.3 `03-练习反馈原文_来源.md`

由用户练习后提供，Codex 负责整理入当天文件夹。

用途：保存 ChatGPT 给用户的原始反馈，尽量不改写，方便回溯。

建议内容：

- 练习时间
- 练习工具，例如 ChatGPT 语音模式
- 使用的指令包
- ChatGPT 原始反馈
- 用户补充说明，例如“我觉得哪里最卡”

如果用户只把反馈粘贴到对话里，Codex 应先确认是否需要写入当天工作区。默认可以先在对话中结构化总结。

### 3.4 `04-练习反馈结构化沉淀.md`

由 Codex 根据原始反馈生成。

这是最重要的中间文件，用于指导后续素材生成。

固定结构：

```text
# YYYY-MM-DD 练习反馈结构化沉淀

## 练习概览

- 练习场景：
- 来源素材：
- 目标表达：
- 实际完成情况：

## 反馈摘要

用 3-5 句话总结本次练习最重要的信息。

## 表达问题

- 问题：
  - 更自然表达：
  - 后续练习动作：

## 语法问题

- 问题：
  - 正确版本：
  - 后续练习动作：

## 流利度问题

- 卡点：
  - 可能原因：
  - 后续练习动作：

## 场景应对问题

- 场景任务是否完成：
- 哪一步做得好：
- 哪一步需要加强：

## 可复用表达

- 表达：
  - 使用场景：
  - 用户自己的例句：

## 下一次练习建议

- 推荐场景：
- 推荐目标表达：
- 推荐练习方式：

## 标签

- scene:
- skill:
- issue:
- expression:
- priority:
```

## 4. 指导后续内容生成

Codex 之后生成每日素材包时，应回溯最近 7-14 天的 `04-练习反馈结构化沉淀.md`。

重点检查：

- 最近反复出现的表达问题
- 最近反复出现的语法问题
- 用户已经学过但还没熟练使用的表达
- 高频卡住的场景
- ChatGPT 给出的下一次练习建议
- 哪些技能标签近期需要继续覆盖

每日素材包生成时应把这些信息转化为：

- 今日主题选择
- 口语场景选择
- 目标表达复用
- 复习任务
- 是否减少新输入、增加复用输出

原则：

```text
近期高频卡点 > 新主题扩展
已学表达复用 > 盲目增加新表达
真实场景迁移 > 抽象题目练习
```

## 5. 系统记录候选

`06-系统记录候选.md` 用于承接“将来写入 RuLingo 系统”的内容。它不是最终数据库格式，但应尽量接近未来系统可展示的信息。

建议结构：

```text
# YYYY-MM-DD 系统记录候选

## 今日练习

- 练习类型：
- 练习场景：
- 使用素材：
- 目标表达：
- 完成状态：

## 今日反馈

- 表达：
- 语法：
- 流利度：
- 场景应对：

## 需要加强

- 能力标签：
- 具体问题：
- 下一步练习：

## 可复习内容

- 可复用表达：
- 用户例句：
- 推荐复习日期：
```

未来系统页面可以基于这些字段展示：

- 今天练习了什么内容
- 从练习中得到哪些反馈
- 哪些地方需要加强
- 可以做哪些针对性练习
- 最近 7 天高频问题和复习建议

## 6. 当天工作流

推荐执行顺序：

1. Codex 生成 `01-今日素材包_主题.html`，并在其中内嵌语音陪练指令包。
2. 用户点击 HTML 中的复制按钮，把语音陪练指令复制到 ChatGPT 语音模式。
3. 用户复制指令包到 ChatGPT 语音模式练习。
4. 用户把 ChatGPT 反馈贴回给 Codex。
5. Codex 整理 `03-练习反馈原文_来源.md`。
6. Codex 生成 `04-练习反馈结构化沉淀.md`。
7. Codex 生成或更新 `05-后续计划建议.md`。
8. 如用户需要，Codex 生成 `06-系统记录候选.md`。

## 7. 后续调整方式

用户可以直接用自然语言调整这份规则，例如：

```text
我不想每天保存原文，只保存结构化沉淀。
系统记录候选里加一个“自我评分”。
后续计划建议只保留 3 条。
语音反馈要额外记录 pronunciation。
```

调整后应更新本文档，并从下一次学习工作区开始执行。
