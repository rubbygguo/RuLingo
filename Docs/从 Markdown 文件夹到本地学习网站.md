# 从 Markdown 文件夹到本地学习网站

这份文档是给“不写代码也想看懂项目发生了什么”的版本。

一句话概括：我们不是简单做了一个网页，而是把原来散落在文件夹里的英文学习资料，整理成了一个可以长期增长、可以搜索筛选、可以按每日计划使用的本地英文学习系统。

## 1. 最开始是什么状态

最开始，这个项目更像一个资料文件夹。

里面主要是这些 Markdown 文件：

- `00-学习计划/每日英文提升计划.md`
- `01-素材库/...md`
- `02-表达积累/表达库_起步版.md`
- `04-口语练习/口语题库_起步版.md`
- `06-复盘记录/每日打卡模板.md`

Markdown 可以理解成一种“纯文本笔记格式”。它很适合写计划、文章、清单和练习题，但它也有一个问题：当资料越来越多时，它不太像一个系统，更像一堆文档。

比如你以后可能会想问：

- 今天该学哪一份素材？
- 这份素材对应哪些表达？
- 这些表达能不能按 seminar、写作、研究生生活来筛选？
- 某个口语题和哪篇阅读材料有关？
- 我每天打卡、复盘、阶段目标之间有没有关系？

如果所有内容都只是散落在 Markdown 里，这些问题很难自动回答。

## 2. 我们做的核心转变

我们把项目从“文档集合”变成了“数据驱动的网站”。

这个转变可以这样理解：

```text
原来：
一堆 Markdown 文件

现在：
Markdown 原始资料
+ data/ 结构化学习数据
+ src/ React 网站代码
+ Vite 本地服务器
+ 一个可以打开使用的学习工作台
```

也就是说，Markdown 还在，但它不再是唯一的组织方式。真正支撑网站运行的是 `data/` 里的结构化数据，以及 `src/` 里的前端代码。

## 3. 我具体做了哪些事情

### 3.1 保留原始学习资料

原来的学习文件夹没有被丢掉，它们还在：

- `00-学习计划/`
- `01-素材库/`
- `02-表达积累/`
- `03-写作练习/`
- `04-口语练习/`
- `05-阅读精读/`
- `06-复盘记录/`

这些可以理解为“原始笔记区”或“人工编辑区”。你以后仍然可以看它们、改它们、补充它们。

### 3.2 新增 `data/` 数据层

我把原来 Markdown 里比较重要的信息，拆成了更适合网站读取的数据文件。

现在 `data/` 下面有这些模块：

```text
data/
  plans/        学习计划
  materials/    素材库
  expressions/  表达库
  practices/    口语和课程练习
  writings/     写作练习
  checkins/     打卡和复盘
  meta/         系统设置和分类
```

这些文件大部分是 JSON。JSON 可以理解成“给程序看的表格/清单格式”。它比 Markdown 更适合让网页自动读取、筛选、搜索和关联。

例如 `data/plans/daily/2026-05-11.json` 里保存了 2026 年 5 月 11 日的学习计划，包括：

- 今天的学习模式：45 分钟
- 今天的重点：seminar participation and postgraduate study rhythm
- 今天要做的输入、表达、输出、复盘
- 每个任务关联哪一份素材、哪一个练习、哪些表达

这就让网站可以自动生成“今日工作台”。

### 3.3 把素材变成可关联的数据

原来素材是 Markdown 文件，例如：

- `01-素材库/2026-05-06_20分钟练习_研究生时间管理.md`
- `01-素材库/2026-05-07_20分钟练习_Seminar发言.md`

现在它们被整理到了：

```text
data/materials/index.json
data/materials/readings/
```

`index.json` 负责记录每份素材的“档案信息”，比如：

- id
- 标题
- 类型
- 日期
- 标签
- 对应正文文件
- 关联的表达
- 对应的口语和写作任务

正文仍然可以用 Markdown 保存，因为长文本用 Markdown 更舒服。

这一步的意义是：素材不再只是文章，而是可以和表达、练习、计划互相关联的学习资产。

### 3.4 把表达库拆成结构化表达

原来的表达库是一个 Markdown 文件：

```text
02-表达积累/表达库_起步版.md
```

现在被拆成了：

```text
data/expressions/index.json
data/expressions/academic-discussion.json
data/expressions/postgraduate-life.json
```

每个表达可以有：

- 英文表达
- 中文意思
- 示例句
- 标签
- 来源素材
- 分类

这样网站就可以做“表达库”页面，也可以把某篇素材相关的表达自动显示出来。

### 3.5 把口语题库变成练习库

原来的口语题库是 Markdown：

```text
04-口语练习/口语题库_起步版.md
```

现在被整理进：

```text
data/practices/index.json
```

每个练习有：

- 题目
- 类型，比如 speaking
- 时长，比如 30-60 seconds 或 2 minutes
- prompt
- 可套用的句型框架
- 标签
- 关联素材

所以网站里可以显示“口语和课程练习”，也可以按时长筛选。

### 3.6 建立了 React 网站

我新增了：

```text
src/App.jsx
src/main.jsx
src/dataClient.js
src/styles.css
site/index.html
```

这些文件组成了真正的网站界面。

可以粗略理解为：

- `site/index.html`：网页入口，像房子的门。
- `src/main.jsx`：把 React 应用挂到网页上，像把系统启动起来。
- `src/App.jsx`：主要界面逻辑，决定页面有哪些模块、按钮、卡片、搜索和筛选。
- `src/dataClient.js`：负责从 `data/` 读取学习数据。
- `src/styles.css`：负责页面长什么样，包括颜色、布局、按钮、卡片、侧边栏。

现在网站里有这些主要区域：

- 今日工作台
- 素材库
- 表达库
- 口语和课程练习
- 写作练习
- 复盘模板

### 3.7 加入搜索和筛选

网站现在不是静态展示文字，而是有交互。

比如：

- 左侧可以搜索素材、表达、题目。
- 素材库可以按标签筛选。
- 练习库可以按练习时长筛选。
- 今日工作台可以切换 20 分钟、45 分钟、90 分钟模式。

这就是从“文档”走向“应用”的重要区别。

### 3.8 配置了 Vite 本地开发服务器

我新增了：

```text
package.json
package-lock.json
vite.config.js
```

它们的作用是让这个网站能在你电脑本地跑起来。

这里用到的是 Vite。你可以把 Vite 理解成一个“本地网站启动器”。它负责：

- 启动一个本地网址
- 让 React 代码能运行
- 让浏览器能读取 `data/` 里的 JSON 和 Markdown

现在项目默认访问地址是：

```text
http://localhost:4173/site/
```

这里的 `localhost` 意思是“你自己这台电脑”，不是互联网上的公开网站。

### 3.9 给 `data/` 做了本地读取通道

普通浏览器页面不能随便读取你电脑上的任意文件，这是安全限制。

所以我在 `vite.config.js` 里加了一个本地数据读取插件。它只允许网站读取项目里的 `data/` 目录。

这一步很关键：它让 React 页面可以通过 `/data/...` 读取学习数据，同时又不会开放整个电脑文件系统。

### 3.10 做了双击启动脚本

我新增了：

```text
启动英文提升系统.command
```

它的作用是让你不用记命令。

你双击它时，它会：

1. 进入项目目录。
2. 检查有没有 npm。
3. 如果还没有依赖，就运行 `npm install`。
4. 启动网站。
5. 打开浏览器访问 `http://localhost:4173/site/`。

对你来说，它就是“启动按钮”。

### 3.11 写了系统设计文档

我还新增了：

```text
Docs/系统设计.md
```

那份文档偏正式，讲这个系统未来应该怎么扩展，包括：

- 本地优先
- 数据和展示分离
- JSON + Markdown 混合存储
- 学习计划、素材库、表达库、写作、练习、复盘这些模块
- 未来如何继续增长

你现在正在看的这份文档，则更偏“过程回顾”和“概念解释”。

## 4. 现在这个项目的结构怎么理解

你可以把现在的项目想成四层。

### 第一层：原始资料层

```text
00-学习计划/
01-素材库/
02-表达积累/
03-写作练习/
04-口语练习/
05-阅读精读/
06-复盘记录/
```

这是你最容易直接读懂和编辑的地方。

### 第二层：数据层

```text
data/
```

这是网站真正读取的学习数据。它把计划、素材、表达、练习和复盘变成结构化内容。

### 第三层：网站代码层

```text
src/
site/
```

这是网站界面和交互逻辑。它负责把数据变成你能看的页面。

### 第四层：运行配置层

```text
package.json
vite.config.js
node_modules/
启动英文提升系统.command
```

这是让网站能启动、能运行的基础设施。

## 5. 你需要学习和弄懂的关键概念

你不需要一下子学成程序员。你只需要按优先级理解这些概念。

### 5.1 文件夹结构

先弄懂每个文件夹是干什么的。

最重要的是：

- `data/`：网站读取的数据。
- `src/`：网站的代码。
- `Docs/`：说明文档。
- 原来的中文编号文件夹：原始学习资料。

学会这一点，你就知道“新增内容应该放哪里”。

### 5.2 Markdown

Markdown 是适合人写的文本格式。

你需要知道：

- `#` 是一级标题。
- `##` 是二级标题。
- `-` 是列表。
- Markdown 适合写长文章、学习材料、复盘、草稿。

这个你已经基本在用了。

### 5.3 JSON

JSON 是适合程序读取的数据格式。

它长这样：

```json
{
  "title": "Seminar 发言",
  "tags": ["seminar", "academic discussion"],
  "durationMinutes": 20
}
```

你需要理解几件事：

- `{}` 表示一个对象。
- `[]` 表示一个列表。
- 每个字段通常是 `"名字": "内容"`。
- JSON 里的逗号、引号、括号不能随便漏掉。

未来你想自己维护 `data/`，JSON 是最值得优先学的概念。

### 5.4 id 和关联关系

这是这个系统最重要的概念之一。

例如：

```json
"materialId": "material-2026-05-07-seminar-speaking"
```

这句话的意思是：这个任务关联到某一份素材。

再比如：

```json
"suggestedExpressionIds": [
  "expr-the-author-seems-to-argue-that",
  "expr-to-some-extent"
]
```

意思是：今天建议复习这些表达。

id 就像每个学习内容的身份证。网站靠 id 把计划、素材、表达、练习串起来。

### 5.5 数据和展示分离

这是从“笔记”升级到“系统”的核心。

意思是：

- 学习内容不要直接写死在网页里。
- 学习内容放在 `data/`。
- 网页代码只负责读取和展示。

好处是：以后你新增一份素材，理论上只要补数据，网站就能显示，不需要重写页面。

### 5.6 React

React 是做网页界面的工具。

在这个项目里，你不需要一开始掌握 React 的全部细节。你只需要知道：

- React 把页面拆成一个个组件。
- 组件就是页面上的一块功能，比如侧边栏、素材卡片、表达卡片、今日计划。
- `src/App.jsx` 是当前最核心的页面文件。

以后如果你想改页面长什么样、增加一个模块，就会涉及 React。

### 5.7 Vite

Vite 是启动本地网站的工具。

你可以简单理解为：

- React 是“网站怎么写”。
- Vite 是“怎么把网站跑起来”。

你运行：

```bash
npm run dev
```

Vite 就会启动本地网站。

### 5.8 npm 和 node_modules

npm 是 JavaScript 项目的包管理工具。

`package.json` 里写着这个项目需要哪些工具：

- React
- React DOM
- Vite
- Vite React 插件

`node_modules/` 是这些工具下载后的存放位置。它通常很大，你不需要手动修改它。

### 5.9 CSS

CSS 负责网页样式。

本项目的样式主要在：

```text
src/styles.css
```

它决定：

- 页面布局
- 颜色
- 字体
- 卡片
- 按钮
- 侧边栏
- 响应式显示

如果以后你想改“看起来如何”，大概率会改 CSS。

### 5.10 本地网站和公开网站

现在这个项目是本地网站。

它运行在：

```text
http://localhost:4173/site/
```

这表示只有你这台电脑在运行它。它不是一个发布到互联网上的网站。

如果未来想让别人访问，就需要学习：

- build
- 部署
- 静态网站托管
- 域名

但现在阶段不急。

## 6. 你以后怎么新增内容

最简单的原则是：先判断它属于哪个模块。

如果是新的每日计划，放到：

```text
data/plans/daily/
```

如果是新的阅读素材，通常要改两个地方：

```text
data/materials/index.json
data/materials/readings/
```

如果是新的表达，放到：

```text
data/expressions/
```

如果是新的口语或课程练习，放到：

```text
data/practices/index.json
```

如果是新的复盘模板或打卡记录，放到：

```text
data/checkins/
```

现在最容易出错的地方是 JSON 格式。比如少一个逗号、多一个逗号、引号没闭合，网站就可能读取失败。

## 7. 当前系统还没有做什么

为了避免你误会，我也把边界说清楚。

现在这个系统已经能读取和展示本地数据，但它还不是一个完整的后台管理系统。

目前还没有：

- 在网页里新增素材的表单
- 在网页里直接保存打卡
- 用户登录
- 云端同步
- 数据库
- 自动生成每日计划
- 复杂复习算法

现在更准确的定位是：

```text
本地数据驱动的英文学习工作台
```

它已经比普通 Markdown 文件夹更系统，但还没有发展到完整 App 的程度。

## 8. 你接下来最值得学的路线

如果你想慢慢看懂这个项目，我建议按这个顺序：

1. 先看懂项目文件夹结构。
2. 学会 Markdown 的基本写法。
3. 学会 JSON 的基本格式。
4. 理解 id 如何把计划、素材、表达、练习关联起来。
5. 理解 `data/` 和 `src/` 的区别。
6. 学会用 `启动英文提升系统.command` 启动网站。
7. 再慢慢看 `src/App.jsx` 里的 React 组件。
8. 最后再看 `vite.config.js` 和 `package.json`。

对你来说，最关键的不是一开始学 React，而是先理解：

```text
内容放在哪里
数据怎么组织
页面怎么读取数据
不同内容之间怎么关联
```

这四件事懂了，你就能真正掌控这个系统，而不是只会双击打开它。

## 9. 最后用一句话总结

我们做的事情，是把一个“英文学习资料文件夹”，升级成了一个“本地运行的英文学习系统”。

原来的 Markdown 负责保存人能读的内容；新的 JSON 负责保存程序能理解的数据；React 负责把这些数据展示成网站；Vite 负责让网站在你电脑上运行；启动脚本负责让你不用记命令也能打开它。

这就是这次演化的主线。
