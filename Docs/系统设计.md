# 英文提升学习系统设计文档

## 0. 设计文档体系

RuLingo 的设计文档分为两类：

- 系统设计文档：放在 `Docs/` 和 `Docs/RuLingo系统设计/`，用于记录系统模块、数据库、上传流程、待确定需求和实现方案草案。
- 每日执行规则：放在 `materials-system/rules/`，用于约束每日素材包、语音陪练指令包和学习工作区如何生成。

当前系统设计草案包括：

```text
Docs/RuLingo系统设计/语音练习记录上传设计草案.md
```

后续凡是“需求还没完全想好，但需要先记录下来继续讨论”的内容，优先放入 `Docs/RuLingo系统设计/`。

## 1. 项目定位

本项目不是一个 Markdown 资料展示页，而是一个本地运行、长期积累、由数据驱动的个人英文学习系统。

系统的核心目标是帮助用户持续完成英文输入、表达积累、写作输出、课程/科学练习和复盘，并把每次新增的学习内容沉淀为可检索、可关联、可复用的数据资产。

## 2. 设计原则

### 2.1 本地工作区 + 远程系统记录

系统早期以本地项目目录为主，但当前已经演进为“本地工作区 + CloudBase 远程记录”的混合形态。

本地项目目录负责承载：

- 每日素材包
- 语音陪练指令包
- 练习反馈原文
- 结构化沉淀草稿
- 待确认的系统记录候选

CloudBase MySQL 负责承载：

- 每日任务完成状态
- 未来的语音练习记录
- 未来的反馈、复习和长期学习统计

原则是：需要用户和 Codex 共同整理、审核、修改的内容先留在本地工作区；确认要进入 RuLingo 系统展示和长期统计的内容，再通过明确上传流程进入 CloudBase。

### 2.2 数据和展示分离

长期系统不应该把学习内容写死在 HTML 中。

正确结构应该是：

```text
data/ 中的学习数据 -> site/ 中的网站读取数据 -> 生成可交互界面
```

网站负责展示、搜索、筛选、关联和学习流程入口；`data/` 负责保存真正的内容资产。

### 2.3 数据格式按场景选择

系统不强制所有内容都使用同一种格式。不同类型的数据可以选择最适合的存储方式。

- JSON：适合结构化数据、索引、标签、任务、关联关系、网页直接读取。
- Markdown：适合长文本、阅读材料、写作草稿、精修版本、反思记录。
- SQLite：适合未来大量打卡记录、练习历史、复习调度、复杂查询。
- YAML：适合人工可读的配置，但网页读取需要额外转换，优先级低于 JSON。

初期优先采用 `JSON + Markdown` 的混合方案。等数据量和查询复杂度上升后，再考虑引入 SQLite。

### 2.4 可持续增长

之后新增内容时，应该优先判断它属于哪种系统数据，而不是随手创建新的散乱 Markdown。

例如：

- 新学习计划：进入 `data/plans/`
- 新素材：进入 `data/materials/`
- 新表达：进入 `data/expressions/`
- 新写作：进入 `data/writings/`
- 新课程/科学练习：进入 `data/practices/`
- 新打卡或复盘：进入 `data/checkins/`

### 2.5 数据之间要能关联

系统中的内容不应互相孤立。

例如，一份每日学习计划可以关联：

- 今日素材
- 今日表达
- 今日写作任务
- 今日口语或课程练习
- 今日复盘记录

一篇素材也可以关联：

- 它产出的表达
- 它对应的口语题目
- 它对应的写作任务
- 它所属的学习场景

这种关联关系是系统从“资料库”升级为“学习工作台”的关键。

## 3. 目标用户和使用场景

当前用户背景：

- 香港研究生在读
- 英文水平约雅思 6.5
- 目标是提升到更自然、更准确、更有学术/职业表达力的英文使用状态
- 高频场景包括课堂阅读、seminar 讨论、presentation、essay/report 写作、邮件沟通和日常社交

典型使用场景：

1. 打开系统，查看今天应该做什么。
2. 选择 20 分钟、45 分钟或 75-90 分钟学习模式。
3. 阅读或听一份素材。
4. 从素材中积累表达。
5. 完成写作、口语或课程练习。
6. 记录当天复盘。
7. 以后搜索和复用已积累的素材、表达和练习记录。

## 4. 核心模块

### 4.1 学习计划

学习计划模块负责管理每日、每周和阶段性学习安排。

应支持：

- 20 分钟保底版
- 45 分钟最低可执行版
- 75-90 分钟标准提升版
- 每周安排
- 30 天阶段目标
- 与素材、表达、练习和复盘的关联
- 未来每日自动生成或半自动生成学习任务

建议数据位置：

```text
data/plans/
  routines.json
  weekly.json
  milestones.json
  daily/
```

适合格式：

- 结构化计划：JSON
- 长说明或阶段复盘：Markdown

### 4.2 素材库

素材库负责保存输入材料，包括阅读、听力、课堂材料、seminar 主题、考试材料等。

应支持：

- 分类：reading、listening、lecture、seminar、exam、assignment
- 标签：academic writing、seminar、time management、presentation 等
- 难度或阶段
- 正文内容
- 可学习表达
- 关联任务
- 来源和日期

建议数据位置：

```text
data/materials/
  index.json
  readings/
  listenings/
  courses/
```

适合格式：

- 素材元信息和索引：JSON
- 长篇正文：Markdown
- 小型素材：可以直接放在 JSON 的 `content` 字段中

### 4.3 表达积累

表达积累模块负责保存短语、搭配、句型、句子框架和使用场景。

应支持：

- 表达原文
- 中文含义
- 原句
- 用户自己的句子
- 使用场景
- 标签
- 来源素材
- 熟悉度或复习状态

建议数据位置：

```text
data/expressions/
  index.json
  academic-discussion.json
  postgraduate-life.json
```

适合格式：

- JSON

### 4.4 写作练习

写作练习模块负责保存用户的英文输出和修改过程。

应支持：

- 写作题目
- 初稿
- 修改稿
- correctness 修改
- naturalness 修改
- sophistication 修改
- 常见错误
- 关联表达
- 关联素材
- 日期和字数

建议数据位置：

```text
data/writings/
  index.json
  drafts/
  revisions/
```

适合格式：

- 写作元信息：JSON
- 正文和修改稿：Markdown

### 4.5 科学练习 / 课程练习

该模块用于承载更贴近专业、课程、seminar、presentation 和 assignment 的训练。

“科学练习”可以理解为更系统、更有反馈闭环的练习设计；“课程练习”则更贴近真实课程任务。命名可在后续根据实际使用进一步确定。

应支持：

- 课程相关练习
- seminar 发言练习
- presentation opening / Q&A 练习
- assignment brief 分析
- reading response
- academic reflection
- 专业话题表达训练

建议数据位置：

```text
data/practices/
  index.json
  speaking/
  writing/
  course/
  presentation/
```

适合格式：

- 练习元信息、题目、步骤：JSON
- 长答案、示范答案、反馈：Markdown

### 4.6 复盘和打卡

复盘模块记录每日完成情况和学习反馈。

应支持：

- 日期
- 今日模式：20 / 45 / 90 分钟
- 今日材料
- 今日表达
- 今日输出
- 卡住的地方
- 明天刻意练习
- 完成状态

建议数据位置：

```text
data/checkins/
  2026/
    05.json
```

适合格式：

- 初期：按月份 JSON
- 后期：如果记录量大、需要统计和复杂查询，可以迁移到 SQLite

## 6. 数据模型草案

```json
{
  "id": "material-2026-05-07-seminar-speaking",
  "title": "Seminar 发言",
  "type": "reading",
  "level": "intermediate",
  "date": "2026-05-07",
  "scenes": ["seminar", "academic discussion"],
  "tags": ["participation", "confidence", "sentence frames"],
```

## 7. 网站功能规划

### 7.1 第一阶段：数据驱动展示

目标：把当前静态 HTML 改造成读取 `data/` 的网站。

功能：

- 从 JSON 读取学习计划、素材、表达、练习和复盘模板
- 模块化展示
- 搜索
- 标签筛选
- 基础详情页或详情面板

### 7.2 第二阶段：学习工作台

目标：让系统成为每日学习入口。

功能：

- 今日计划
- 20 / 45 / 90 分钟模式切换
- 今日素材入口
- 今日表达目标
- 今日输出任务
- 今日复盘入口
- 完成状态展示

### 7.3 第三阶段：积累和复用

目标：让用户能看见长期积累。

功能：

- 表达库按场景、标签、来源筛选
- 素材和表达互相跳转
- 写作练习和反馈归档
- 打卡历史
- 高频问题和高频表达统计

### 7.4 第四阶段：更强的本地系统能力

可能方向：

- 引入 SQLite 存储打卡、复习记录和练习历史
- 增加本地数据导入/导出
- 增加复习提醒或间隔复习状态
- 增加课程维度的学习档案

## 8. 新增内容时的工作流程

以后每次用户提出“加内容”或“生成计划”时，应按下面流程处理：

1. 判断内容类型：计划、素材、表达、写作、练习、复盘或配置。
2. 判断存储格式：JSON、Markdown 或未来 SQLite。
3. 将内容写入 `data/` 对应目录。
4. 如有必要，更新索引文件。
5. 建立关联关系，例如素材关联表达、计划关联素材和练习。
6. 确认网站能读取并展示新增内容。
7. 只在确有必要时修改 `site/` 展示逻辑。

## 9. 当前迁移建议

当前项目已有目录：

```text
00-学习计划/
materials-system/
02-表达积累/
03-写作练习/
04-口语练习/
05-阅读精读/
06-复盘记录/
site/
```

建议后续迁移步骤：

1. 创建 `data/` 目录和基础子目录。
2. 将现有 Markdown 内容转换为初始 JSON/Markdown 混合数据。
3. 将 `site/index.html` 中写死的内容拆出到 `data/`。
4. 拆分网站文件为 `index.html`、`styles.css`、`app.js`。
5. 让网站从 `data/` 读取内容。
6. 保留原 Markdown 作为历史材料，或迁移到 `legacy/markdown/`。

## 10. 未决问题

以下问题可以在后续实现时逐步决定：

- “科学练习”和“课程练习”最终采用哪个模块名称，或是否并列存在。
- 是否需要浏览器内直接编辑数据，还是继续由 Codex 负责写入本地数据文件。
- 初期是否使用本地开发服务器，还是保持可直接打开的静态页面。
- 何时引入 SQLite。
- 是否需要用户可视化创建计划、素材和表达的表单。

## 11. 总结

本系统的长期方向是：

> 一个本地数据驱动的个人英文学习系统。`data/` 保存持续增长的学习资产，`site/` 提供可浏览、可搜索、可执行学习流程的界面。系统通过计划、素材、表达、写作、课程练习和复盘之间的关联，帮助用户把每日学习沉淀成长期可复用的英文能力。
