# RuLingo 文档

这个目录用于集中保存 RuLingo 的产品需求、系统设计、数据库脚本和使用说明。

每日素材生成和学习工作区的执行规则仍放在：

```text
materials-system/rules/
```

## 目录结构

```text
docs/
  product/       产品需求、能力边界、待确认工作流
  architecture/  系统设计、数据流、上传 / 同步方案
  database/      CloudBase MySQL schema 和迁移脚本
  guides/        面向使用者或搭建过程的说明文档
```

## 放置规则

适合放在 `docs/` 的内容：

- 系统模块设计
- 数据库表设计草案
- 上传 / 同步 / 数据流方案
- 待确认需求
- 未来实现路线
- 前端展示方案
- 本地脚本和 CloudBase 之间的协作方案

不适合放在 `docs/` 的内容：

- 每天生成的临时素材包
- 每天练习后的原始反馈
- 单次学习任务内容
- 具体每日素材生成规则

## 当前文档

- `product/当前系统需求.md`：记录 RuLingo 当前已经确认的产品需求、能力边界和待后续设计的问题。
- `product/语言记忆库需求草案.md`：记录类似“生词本”但更偏长期语言记忆库的产品需求。
- `architecture/系统设计.md`：系统定位、数据和展示分离原则、长期数据模型方向。
- `architecture/语音练习记录上传设计草案.md`：讨论如何把每日语音练习沉淀上传到 CloudBase MySQL，并让 RuLingo 前端读取展示。
- `database/`：CloudBase MySQL schema、DailyPack 表结构和迁移 SQL。
- `guides/从零搭建个人语言学习系统.md`：面向非技术背景使用者的项目搭建复盘。

## 文档状态标记

后续每份设计文档建议在开头标注状态：

```text
状态：草案 / 待讨论 / 已确认 / 已实现 / 已废弃
```

含义：

- 草案：只是初步想法，不代表要实现。
- 待讨论：方向基本明确，但关键问题未定。
- 已确认：可以进入实现设计或开发。
- 已实现：代码或数据结构已经落地。
- 已废弃：保留历史，但不再按此执行。
