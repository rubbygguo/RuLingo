# 从零搭建个人语言学习系统

这份文档写给没有技术背景、但想学习如何用 Codex 一步一步搭建自己系统的人。

它不是一份单纯的技术说明，而是一份项目复盘：我们从一个普通的英文学习资料文件夹出发，借助 Codex，把它慢慢整理成了一个可以本地运行、可以搜索筛选、可以查看每日任务、可以记录完成状态的英文学习网站。

一句话概括：

```text
先把想法说清楚，再让 Codex 帮我们把资料、数据、页面、运行方式一点点搭起来。
```

## 1. 最开始我们手里有什么

最开始，这个项目更像一个学习资料文件夹。

里面有这些人工整理的 Markdown 文件：

```text
00-学习计划/每日英文提升计划.md
materials-system/rules/...
materials-system/daily-packs/...
02-表达积累/表达库_起步版.md
03-写作练习/README.md
04-口语练习/口语题库_起步版.md
06-复盘记录/每日打卡模板.md
```

Markdown 可以理解成“适合人看的文本笔记”。它很适合写学习计划、文章、表达清单、口语题和复盘模板。

但当资料越来越多时，问题也会出现：

- 今天到底该学什么？
- 某份素材能不能和口语、写作任务关联起来？
- 表达库能不能按主题筛选？
- 我能不能只看 seminar、academic writing、postgraduate life 相关内容？
- 每天完成了哪些任务，有没有进度感？

如果所有内容都只是散落在 Markdown 文件里，它们还是“资料”，还没有形成“系统”。

## 2. 我们真正要解决的问题

这个项目的目标不是炫技，也不是一上来做一个复杂 App。

我们真正要做的是：

```text
让一个非技术背景的人，也能用本地文件和 Codex，搭出一个可持续增长的学习系统。
```

所以项目有三个核心原则：

1. 内容仍然放在本地，自己能掌控。
2. 学习资料不只收藏，还要能变成任务。
3. 每一步都让 Codex 参与，但人来决定学习目标和使用场景。

这也是为什么我们后来专门写了 [学习素材来源与场景设计](../materials-system/rules/学习素材来源与场景设计.md)。那份文档说明：素材库不应该只是“英语资料收藏夹”，而应该围绕真实任务组织。

当前最重要的使用者画像是：

- 香港研究生在读
- 需要 academic reading、seminar discussion、presentation、writing、career English
- 希望把听说读写变成每天能执行的小任务

所以我们把素材组织逻辑定成：

```text
场景 -> 任务 -> 技能 -> 素材 -> 练习输出
```

例如：

```text
学术场景 -> seminar 发言 -> 听 + 说 -> 一段课堂讨论材料 -> 60 秒观点回应
职业场景 -> networking -> 读 + 写 + 说 -> LinkedIn message 样例 -> 写一条邀约消息
生活场景 -> 给教授写邮件 -> 读 + 写 -> model email -> 写一封请求延期邮件
```

## 3. 第一阶段：让 Codex 先理解项目

对小白来说，最重要的不是先学代码，而是学会向 Codex 说明问题。

一开始可以这样问 Codex：

```text
请你先阅读当前项目结构，告诉我这些文件夹分别是干什么的。
不要急着改代码，先用小白能懂的话解释。
```

Codex 会去看项目里的文件夹、Markdown 文档和已有代码，然后帮我们建立一个整体地图。

这一阶段的产出不是代码，而是理解：

- 哪些文件是原始学习资料
- 哪些内容可以变成结构化数据
- 哪些内容适合网页展示
- 哪些内容暂时只需要继续保存在 Markdown 里

这一步非常关键。因为非技术背景的人最容易卡住的地方不是“不会写代码”，而是“不知道自己要让代码解决什么问题”。

## 4. 第二阶段：把资料从 Markdown 整理成数据

接下来，我们让 Codex 帮忙做了一个核心转变：

```text
从“Markdown 文件夹”
变成
“Markdown 原始资料 + data 结构化数据”
```

现在项目里有一个很重要的目录：

```text
data/
```

它下面分成这些模块：

```text
data/
  plans/        学习计划
  materials/    素材库
  expressions/  表达库
  practices/    口语和课程练习
  writings/     写作练习
  checkins/     打卡和复盘
  meta/         系统设置和分类
```

为什么要这样做？

因为 Markdown 适合人读，JSON 适合程序读。

例如，Markdown 可以写一篇完整的素材说明；但如果网站要筛选“seminar 相关素材”，它需要更稳定的字段，例如：

```json
{
  "id": "material-2026-05-07-seminar-speaking",
  "title": "Seminar 发言",
  "tags": ["seminar", "academic discussion"],
  "durationMinutes": 20
}
```

你可以把 JSON 理解成“给网站看的表格”。网站靠这些字段来搜索、筛选、关联和展示。

这一阶段可以这样让 Codex 工作：

```text
请把现有 Markdown 资料整理成 data/ 目录下的结构化 JSON。
要求保留原始 Markdown，不要删除原始资料。
每份素材要有 id、标题、日期、标签、关联表达和练习任务。
```

这里人负责判断内容价值，Codex 负责把内容整理成程序能使用的结构。

## 5. 第三阶段：建立“关联关系”

一个系统和一堆文件最大的区别，是内容之间能互相连接。

这个项目里最重要的连接方式是 `id`。

例如：

```json
"materialId": "material-2026-05-07-seminar-speaking"
```

这表示某个任务关联到一份素材。

再比如：

```json
"suggestedExpressionIds": [
  "expr-the-author-seems-to-argue-that",
  "expr-to-some-extent"
]
```

这表示今天建议复习这些表达。

`id` 就像每个学习内容的身份证。Codex 帮我们把计划、素材、表达、口语题、写作任务串起来之后，网站就不只是展示文字，而是可以回答：

- 这份素材对应哪些表达？
- 这道口语题来自哪个场景？
- 今天的任务需要用哪些材料？
- 哪些练习属于 postgraduate life？

小白需要理解的不是复杂代码，而是这个原则：

```text
内容有了稳定 id，系统才能把它们连接起来。
```

## 6. 第四阶段：先做一个能打开的网站

当数据层有了之后，我们让 Codex 搭了前端页面。

现在网站代码主要在：

```text
src/
```

一开始的目标很朴素：

```text
把 data/ 里的学习数据读取出来，展示成一个本地网页。
```

项目里有这些关键文件：

```text
src/LearningApp.jsx   主要学习界面
src/dataClient.js     读取 data/ 数据
src/styles.css        页面样式
src/pages/index.jsx   首页路由
src/pages/today.jsx   今日计划页路由
src/app.jsx           Mantine 主题和全局样式入口
```

可以这样理解：

- `data/` 负责保存学习内容。
- `src/dataClient.js` 负责把内容读进来。
- `src/LearningApp.jsx` 负责决定页面上显示什么。
- `src/styles.css` 负责页面看起来如何。
- `src/pages/` 负责不同网址打开不同页面。

这一阶段可以这样请 Codex：

```text
请用 React 做一个本地学习网站。
它要读取 data/ 里的计划、素材、表达、练习和复盘模板。
先不要做登录、数据库和云同步，只要本地能打开、能搜索、能筛选。
```

这句话很重要，因为它帮我们控制了范围。

小白做项目时最容易犯的错，是一开始就想做“完整 App”。更好的方式是先做一个最小可用版本：

```text
能打开
能看内容
能搜索
能筛选
能继续扩展
```

## 7. 第五阶段：让网站真的能读取本地 data

浏览器出于安全原因，不能随便读取你电脑上的任意文件。

所以我们加了一个本地数据读取通道：

```text
plugins/localDataServer.js
```

它的作用是：

```text
只允许网站读取项目里的 data/ 目录。
```

例如网页访问：

```text
/data/materials/index.json
```

本地开发服务器会把项目里的对应文件返回给网页。

这一步对小白来说不用深究所有代码，只需要理解：

```text
网页不能直接乱翻你的电脑，所以我们给它开了一个很窄的门，只通向 data/。
```

这样既能让网站读到学习数据，又不会把整个电脑文件系统暴露出去。

## 8. 第六阶段：加入搜索、筛选和模块化页面

最早的网站只是把数据展示出来。后来我们继续让 Codex 加了交互。

首页现在主要包括：

- 素材库
- 表达库
- 口语和课程练习
- 写作练习
- 复盘模板

左侧侧边栏可以：

- 搜索素材、表达、题目
- 跳转不同模块
- 进入“今日计划”

素材库可以按标签筛选，练习库可以按练习时长筛选。

这一步的意义是：

```text
网站开始从“展示文档”变成“学习工作台”。
```

可以这样让 Codex 继续迭代：

```text
请给学习网站增加搜索和筛选。
搜索范围包括素材标题、表达、练习题和标签。
筛选先支持素材标签和练习时长。
不要改变 data/ 的基本结构。
```

这类请求里有两个重点：

1. 说清楚用户想做什么。
2. 说清楚不要破坏什么。

## 9. 第七阶段：新增“今日计划”页面

当前项目里一个重要的新变化，是新增了独立的今日计划页：

```text
src/pages/today.jsx
```

对应访问地址：

```text
http://localhost:4173/today
```

它读取的是：

```text
data/plans/daily/2026-05-11.json
```

这份计划把当天任务拆成四类：

- 听
- 说
- 读
- 写

每类下面有具体任务，例如：

- 听力练习 20 分钟
- 口语练习 20 分钟
- 阅读两篇文章
- 写一篇短文

今日页还加入了几个更像真实工具的功能：

- 日期切换
- 任务勾选
- 今日完成进度条
- 本周、本月、近 7 天统计
- 每类任务完成率
- 使用 `localStorage` 在浏览器本地保存勾选状态

这一步很适合小白学习“怎么让 Codex 把一个模糊需求拆成具体功能”。

原始需求可能只是：

```text
我想每天打开后知道今天该学什么。
```

Codex 可以把它转成：

```text
今日计划页
日期选择
任务列表
勾选完成
进度条
完成统计
```

这里的关键学习点是：

```text
你不需要一开始知道技术实现，但你要能描述你希望用户怎么使用它。
```

## 14. 小白需要优先理解的概念

不用一开始学完整前端开发。这个项目最值得先懂的是下面这些概念。

### 14.1 Markdown

Markdown 是适合人写的文本格式。

你需要知道：

- `#` 是一级标题
- `##` 是二级标题
- `-` 是列表
- Markdown 适合写长文章、学习材料、复盘、草稿

### 14.2 JSON

JSON 是适合程序读取的数据格式。

它长这样：

```json
{
  "title": "Seminar 发言",
  "tags": ["seminar", "academic discussion"],
  "durationMinutes": 20
}
```

你需要特别注意：

- 字段名和文字通常要用英文双引号
- 列表用 `[]`
- 对象用 `{}`
- 多个字段之间要有逗号
- 最后一个字段后面通常不要多写逗号

JSON 格式错了，网站就可能读取失败。

### 14.3 id

`id` 是内容之间互相关联的关键。

一个素材、一个表达、一个练习、一个计划，都应该有稳定的 id。

### 14.4 数据和展示分离

这是这个系统最重要的设计思想：

```text
学习内容放 data/
网页代码放 src/
原始笔记放中文编号文件夹
```

好处是：以后新增素材时，主要改数据，不需要每次都重写页面。

### 14.5 React

React 是做网页界面的工具。

在这个项目里，你只需要先知道：

- 页面可以拆成组件
- 组件就是页面上的一块功能
- `LearningApp.jsx` 是当前最核心的界面文件

### 14.6 Umi Max

Umi Max 负责开发服务器、路由和插件配置。

现在项目通过 `.umirc.js` 说明：

- 网站基础路径是 `/`
- 首页打开 `src/pages/index.jsx`
- 今日页打开 `src/pages/today.jsx`
- 本地数据插件是 `plugins/localDataServer.js`

### 14.7 npm 和 node_modules

npm 是 JavaScript 项目的包管理工具。

`package.json` 说明项目需要哪些依赖和命令。

`node_modules/` 是依赖下载后的目录，通常很大，不需要手动修改。

### 14.8 CSS

CSS 决定页面样式。

本项目主要样式在：

```text
src/styles.css
```

它控制布局、颜色、按钮、卡片、侧边栏、响应式显示。

## 16. 如何继续新增内容

最简单的判断方法是：先问“这是什么类型的内容”。

如果是新的每日计划，放到：

```text
data/plans/daily/
```

如果是新的阅读或听力素材，通常要改：

```text
data/materials/index.json
data/materials/readings/
```

如果是新的表达，放到：

```text
data/expressions/
```

如果是新的口语或课程练习，放到：

```text
data/practices/index.json
```

如果是新的复盘模板或打卡记录，放到：

```text
data/checkins/
```

如果只是当天学习用的临时素材，可以先放在：

```text
materials-system/daily-packs/YYYY-MM-DD/
```

学习完成后，再让 Codex 总结真正有价值的内容。后续这些内容会上传到系统后台数据库，而不是继续沉淀在项目代码里。

可以这样问：

```text
我新增了一份 Markdown 学习素材。
请帮我判断它应该如何进入 data/：
需要新增哪些 JSON 字段？
应该关联哪些表达、练习和计划？
先告诉我方案，再修改文件。
```

## 17. 如何和 Codex 协作，而不是被代码吓住

这个项目最值得学习的，其实是协作方法。

### 17.1 先描述真实场景

不要一上来问：

```text
帮我写 React 代码。
```

更好的说法是：

```text
我是香港研究生，我每天想练听说读写。
我希望打开网站后能看到今日任务，完成后可以勾选，并看到本周完成率。
```

Codex 更擅长把真实场景转成技术方案。

### 17.2 让 Codex 先解释再动手

当你不确定时，可以说：

```text
先不要修改文件。
请先解释你打算怎么做，用小白能懂的话说明会改哪些文件。
```

等你理解后，再让它执行。

### 17.3 每次只推进一个明确目标

例如：

```text
今天只做“今日计划页”。
不要顺手做登录、数据库、云同步。
```

范围越清楚，项目越不容易失控。

### 17.4 让 Codex 做验证

每次改完都可以要求：

```text
请运行项目或检查构建，确认没有明显报错。
如果不能运行，请说明原因。
```

技术项目不是“写完就完了”，还要验证它真的能跑。

### 17.5 让 Codex 帮你补文档

每做完一个阶段，都可以说：

```text
请把这次改动写进 docs/，用非技术背景的人能懂的话解释。
```

这样项目不会变成只有 Codex 懂、你自己反而看不懂的东西。

## 18. 当前系统还没有做什么

为了避免误会，也要说明边界。

现在这个系统已经能读取和展示本地数据，也能做今日任务勾选和本地统计，但它还不是完整后台管理系统。

目前还没有：

- 在网页里新增素材的表单
- 在网页里直接编辑 JSON
- 多用户登录
- 云端同步
- 真正数据库
- 自动生成每日计划
- 复杂复习算法
- 跨设备同步完成状态

现在更准确的定位是：

```text
本地数据驱动的英文学习工作台
```

它已经比普通 Markdown 文件夹更系统，但还没有发展到完整产品。

## 19. 接下来最值得做的迭代

如果继续往下走，建议按这个顺序：

1. 让今日页支持读取不同日期的计划，而不是固定读取 `2026-05-11.json`。
2. 把今日素材包进一步结构化，关联到当天听说读写任务。
3. 增加“新增素材流程”文档，形成固定模板。
4. 给表达库增加按场景、技能、来源素材筛选。
5. 增加复盘记录页面，让每天的学习反馈也进入系统。
6. 再考虑是否需要网页表单、数据库或云同步。

注意顺序很重要。先把本地系统跑顺，再考虑更复杂的功能。

## 20. 最后总结

这次项目演进的主线是：

```text
普通 Markdown 文件夹
-> 结构化 data 数据
-> 本地 React 学习网站
-> 可搜索筛选的学习工作台
-> 独立今日计划页
-> 可勾选、可统计、可继续扩展的本地学习系统
```

在这个过程中，Codex 不是单纯替你写代码的工具，而是一个协作伙伴：

- 它帮你读项目
- 帮你整理资料
- 帮你设计数据结构
- 帮你写页面
- 帮你连接本地数据
- 帮你解释每一步发生了什么
- 帮你把模糊想法变成可运行的系统

而你真正需要练习的是：

```text
描述真实需求
判断内容价值
控制项目范围
检查结果是否符合自己的学习场景
```

这就是一个非技术背景的人利用 Codex 从零搭建系统的核心路径。
